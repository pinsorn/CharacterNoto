## Feature A — Weighted pick roll (DM chooses mode per roll)

**Now:** `rollRegion` does *independent per-item* drops (each item rolls its own %, can yield 0..N).
**Add:** a second mode *weighted pick* — exactly ONE item per roll, chosen with `dropChance` used as a **relative weight**. The DM picks the mode at roll time (not per region).

### Data
No model change. `dropChance` doubles as the weight in weighted mode (reuse, no new field). UI label clarifies "% / weight".

### Algorithm (`src/lib/loot.js`)
```
rollRegion(region, { randomizeQty, mode = 'independent' }, rng):
  if mode === 'weighted':
    pool = items.filter(it => it.infinite || it.stock > 0)      // skip depleted finite
    totalW = sum(it.dropChance for it in pool)
    if totalW <= 0: return []                                   // nothing available
    r = rng() * totalW
    pick = first item where running sum of dropChance > r
    qty = randomizeQty ? randInt(1, perRoll) : perRoll
    if !pick.infinite: qty = min(qty, pick.stock); pick.stock -= qty
    return [{ name: pick.name, amount: qty }]
  else:
    ...existing independent logic...
```
- Weighted always returns ≤1 item.
- Depletion identical to independent (finite items lose stock; weight 0 once empty).
- `randomizeQty` still applies to the picked item.

### UI (`RegionEditor.svelte`)
Roll panel gains a small mode selector next to "Randomize quantity":
`( ) Independent   ( ) Weighted (pick 1)` — default Independent. Pass `mode` into `rollRegion`.
Optional helper text in weighted mode: "Drop% is used as relative weight."

### Tests (`loot.test.mjs`)
- weighted with scripted rng picks the expected item by cumulative weight.
- weighted skips depleted finite items; depletes the picked one.
- weighted returns [] when pool empty / all weights 0.

**Effort: S–M.** Self-contained; no data migration.

## Feature B — Multi-axis relationships + spider/radar chart

**Now:** an edge is a single directed `label` (e.g. "ally"). Too flat.
**Goal:** the DM defines their own **axes** (Trust, Fear, Respect, Affection, …); each directed relationship rates each axis; a relationship is plotted as a **radar (spider) chart** across those axes.

### Data model (`relationships` store)
```
relationships = {
  axes: [ { id, name, min, max } ],         // DM-defined, GLOBAL set (default 0..10)
  edges: [ { id, from, to, label?, values: { [axisId]: number } } ],
  positions: { [charId]: {x,y} }            // unchanged (node graph)
}
```
- **Axes are global** (one campaign-wide set) so every relationship's radar is comparable.
- Each **axis has its own min/max** → supports both magnitude (0..10) and signed "good/bad" (min −5, max +5). Radar normalizes `(v−min)/(max−min)` → 0..1 radial.
- **Directed values**: A→B and B→A are separate edges with independent values (feelings aren't symmetric).
- **Migration**: existing edges keep `label`; `values` defaults to `{}` (missing axis = min/center on the radar). No axes seeded (DM adds).

### UI (`RelationshipGraph.svelte` + new `RadarChart.svelte`)
1. **Axis manager** (small panel/modal): add / rename / remove axis, set min & max. Removing an axis drops it from radars (values ignored, optionally pruned).
2. **Edge editor**: clicking an edge (graph or list) opens a panel with a slider per axis (range = that axis's min/max) + optional label, and a live **radar preview**.
3. **Radar view** = `RadarChart.svelte` (pure SVG, reusable): spokes per axis, grid rings, axis labels, filled polygon of the normalized values. Overlay the **reverse edge** (B→A) as a dashed second polygon when it exists → see asymmetry at a glance.
4. **Node graph stays** as the overview; optional enhancement: edge thickness or color driven by one chosen "highlight axis" (dropdown) so the web encodes a dimension. (Optional, can defer.)

### RadarChart component (sketch)
```
props: axes: [{name,min,max}], series: [{ label, color, dashed?, values: {axisId:number} }]
- N axes → angle_i = i/N * 2π − π/2
- point_i = center + radius * normalized(value_i) * (cos, sin)
- draw grid rings (e.g. 4), axis spokes + labels, one polygon per series
```
Square SVG (like the graph) so it stays round.

### Edge cases
- 0 axes → radar shows empty/“add axes”; edges fall back to label-only (current behavior).
- 1–2 axes → radar degenerate (a line); still valid, or require ≥3 for the chart and show a bar fallback for <3.
- Missing value for an axis → treat as `min` (center).
- Deleting a character → its edges already filtered out (existing logic); also drop from positions.
- Deleting an axis → keep edge.values keys but ignore; offer a "prune" cleanup.

**Effort: M–L.** Data migration is trivial; the work is the axis manager + per-axis edge editor + RadarChart.
