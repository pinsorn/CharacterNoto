# v3.4 Plan — 3D Dice (Draft, not built)

Goal: replace/augment the dice roller with **real 3D dice**: any number of dice, each with any number of faces, **custom label per face**, dice can differ from each other, with a **shake/tumble animation**.

---

## The hard requirement that drives the design
"**Any number of faces**" + "**custom label per face**". There is no regular polyhedron for arbitrary N (no fair "d7" solid). So a true platonic die only exists for 4/6/8/12/20. For arbitrary N the honest 3D shape is an **N-faced barrel/prism** (faces in a ring around an axis) — which also trivially supports custom labels.

## Approach options

### Option A — CSS 3D "barrel" (recommended, no dependency)
Each die = a CSS `transform-style: preserve-3d` element with **N face `<div>`s** arranged in a ring:
`transform: rotateX(i·360/N) translateZ(r)` (r sized so faces tile a cylinder). Each face div shows its label (any text, any styling).
- **Roll** = set the die's `rotateX` to `-(faceIndex·360/N) - spins·360` with a CSS transition (ease-out ~1.2s) + a little `rotateY/rotateZ` wobble → it tumbles and settles with the chosen face front. A short keyframe "shake" can precede the settle.
- ✅ Any N faces, ✅ custom labels, ✅ N dice (N widgets), ✅ per-die faces, ✅ genuine 3D (perspective + 3D transforms), ✅ shake animation.
- ✅ **Zero new dependency.** Small, fast, easy to verify.
- ⚠️ Not a cube/physics sim — it's a labelled barrel. For arbitrary N that's the correct shape anyway. (Could special-case a CSS **cube** for exactly 6 faces if we want the classic d6 look — optional.)

### Option B — Three.js (+ optional cannon-es physics)
Real 3D polyhedra (platonic for 4/6/8/12/20, generated prism for other N), canvas-texture labels, real or tweened tumble.
- ✅ Most "real" look; real physics possible.
- ⚠️ Heavy dependency (~Three.js bundle), arbitrary-N still falls back to a prism, much more code, slower to build + verify. Over-engineered for a single-user tool unless you specifically want cube-physics realism.

**Recommendation: Option A (CSS 3D barrel).** Hits every requirement with no dependency; "real 3D" via CSS perspective. Add a CSS cube for the 6-face case if you want the classic die look.

---

## Data model
```
diceSet = persisted('diceSet', [ { id, faces: [string, ...] } ])   // any number of dice, each any faces
```
- Presets to fill faces fast: d4/d6/d8/d10/d12/d20 → numbers 1..N; "dN" → prompt N; "custom" → free labels.
- Per-die face editor (list of label inputs, add/remove). Add/remove dice.

## Roll
- Each die: pick `idx = floor(rng()*faces.length)` (uniform). Animate barrel to bring face `idx` to front (with spins + wobble). Stagger dice start by ~80ms for flavour.
- Result panel: each die's landed label; if every landed label is numeric → show the **sum**.
- Pure `rollDiceSet(diceSet, rng)` → `[{id, idx, label}]` extracted into `lib/dice3d.js` with a node self-check (uniformity / bounds), so the logic is tested even though the animation isn't.

## UI (Dice tab)
- **Dice builder**: list of dice, each an editable face list + presets; add/remove die.
- **3D dice row**: the animated barrels.
- **Roll** button (+ optional "Roll again"); results + sum.
- Keep it on the existing **Dice** tab.

## Decisions — RESOLVED ✅
- **D1 → Three.js + physics.** Render real 3D meshes with Three.js; tumble with **cannon-es** physics. ✅
- **D2 → keep both.** Notation roller (`2d6+3`) stays; add the 3D dice builder alongside on the Dice tab. ✅
- **D3 → barrel for all N.** Every die is an N-gon prism (no cube special-case). ✅

### Engineering notes (how physics + fairness + barrel-N reconcile)
- Geometry: procedural **N-gon prism** (`CylinderGeometry` with N radial segments, flat-shaded) per die; each of the N side faces gets a **canvas-texture label** (material group per face).
- Physics: **cannon-es** rigid bodies (a Cylinder/box approximation) thrown into a walled tray with gravity → real tumble + bounce ("shake").
- **Result is a predetermined uniform RNG pick** (`floor(rng()·N)`), and after the die comes to rest its orientation is eased so the chosen side face points up/at-camera. This guarantees **fair** results, **consistent** display (shown face == result), and avoids the arbitrary-N "landed on an end / unreadable face" footgun. Real physics drives the motion; RNG drives the outcome.
- `lib/dice3d.js` holds the pure `rollDiceSet(diceSet, rng)` → `[{id, idx, label}]`, node-tested for bounds/uniformity. Animation is verified by screenshot.
